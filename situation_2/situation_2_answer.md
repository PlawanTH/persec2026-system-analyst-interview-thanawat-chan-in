# Situation 2

### ให้น้องเล่าความคิด
อย่างแรก ให้น้องเล่าวิธี ว่าวิธีแก้ปัญหาหรือวิธีการสร้าง API ของน้องทำอย่างไรบ้าง

ถ้าหากน้องเล่าไม่ได้ แสดงว่าน้องอาจจะไม่เข้าใจเรื่องของการสร้าง API นั้นๆ ก็อาจจะจะต้องให้น้องทำความเข้าใจเรื่อง API นั้นๆใหม่ และลองอธิบายเทียบกับสิ่งที่ทำลงไป ทำแบบนี้ในไล่ไปทุกๆส่วนของงาน จนเจอปัญหา และหาส่วนที่เกี่ยวข้องของปัญหานั้น

### กรณีปัญหาเชิงเทคนิค
ในกรณีที่เกิด Error ด้านเทคนิค ให้น้องเริ่มดูจาก Error Message ว่าเกิดอะไรขึ้น แล้วให้น้องคิดว่า ปัญหานั้นมีอะไรที่เกี่ยวข้องบ้าง เช่น function, data, syntax, library, tools, hardware resource เป็นต้น ซึ่งการคิดหาสิ่งที่เกี่ยวข้อง มักจะใช้ได้ผลดี กับ Error บางชนิดที่อาจจะมีข้อความที่ไม่ตรงไปตรงมาได้ด้วย

### การแก้ปัญหา

เมื่อเจอจุดที่เกิดปัญหาแล้ว และได้สิ่งที่เกี่ยวข้องแล้ว ก็ให้น้องไล่จากจุดที่เกิดปัญหา ย้อนกลับไปเรื่อยๆ โดยอิงจากส่วนที่เกี่ยวข้อง จนเจอต้นตอ หรือ ทำการจำกัด (scope) ปัญหาออกเป็นช่วงว่า น่าจะช่วงไหน ถึงช่วงไหน และทำการ bisection เพื่อความเร็วในการหาต้นตอของปัญหา

หากสามารถรันโปรแกรมโดยใช้ debugging tools ได้ก็สามารถให้น้องลองศึกษาด้วยตัวเองเพื่อใช้ดูค่าต่างๆของตัวแปรได้

อีกวิธีคือ สามารถสนับสนุนให้น้องทำ Unit Test และ Mock Data เพื่อค่อยๆทดสอบสิ่งที่น้องทำมา เพื่อ scope ปัญหาให้แคบขึ้นได้
